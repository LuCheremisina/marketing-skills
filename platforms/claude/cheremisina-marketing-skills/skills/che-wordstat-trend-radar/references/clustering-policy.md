## 1. Карточка кандидата

Для каждого запроса сохранять:

```json
{
  "phrase": "локальный mcp сервер",
  "volume": 89,
  "source_seed_ids": ["seed:mcp-server"],
  "core_entity": "mcp-server",
  "intent": "commercial_research",
  "customer_job_ids": ["job:connect-ai-to-data"],
  "product_ids": ["product:mcp-panel"],
  "audience_ids": ["audience:it"],
  "relevance_level": "direct",
  "coverage_status": "partial",
  "decision": "include",
  "reason_codes": ["DIRECT_PRODUCT_FIT", "ABOVE_VOLUME_THRESHOLD"],
  "cluster_id": "mcp-server__commercial-research__connect-ai-to-data"
}
```

Допустимые решения: `include`, `watch`, `review`, `reject`.

## 2. Порядок ворот

Применять первое подходящее жёсткое правило, затем мягкие:

| Условие | Решение | Код причины |
|---|---|---|
| Совпала запрещённая тема | reject | `FORBIDDEN_THEME` |
| Неразрешимый омоним | reject | `AMBIGUOUS_MEANING` |
| Нет связи с продуктом | reject | `NO_PRODUCT_FIT` |
| Исследовательская близость | review | `EXPLORATORY_FIT` |
| Ниже порога, но обязательная тема | watch | `REQUIRED_BELOW_THRESHOLD` |
| Ниже порога, но есть товар/URL | watch | `EXISTING_EXPOSURE_BELOW_THRESHOLD` |
| Ниже порога без исключений | reject | `BELOW_VOLUME_THRESHOLD` |
| Прямой спрос выше порога | include | `DIRECT_PRODUCT_FIT` |
| Смежный спрос выше порога | include или review | `ADJACENT_PRODUCT_FIT` |

Дополнительные коды: `DUPLICATE_PHRASE`, `NESTED_QUERY`, `WRONG_REGION`, `WRONG_AUDIENCE`, `EDUCATION_INTENT`, `JOB_INTENT`, `NEWS_SPIKE`, `MANUAL_APPROVAL`, `MANUAL_REJECTION`.

## 3. Определение интента

Использовать закрытый список:

- `informational_definition` — понять термин;
- `informational_howto` — выполнить действие;
- `commercial_research` — сравнить варианты;
- `transactional` — купить, заказать, подключить;
- `navigational` — найти бренд или сервис;
- `support` — решить проблему существующего пользователя;
- `education` — обучение и курсы;
- `job` — вакансии и профессии;
- `news` — событие или новость.

Не использовать свободные названия интентов.

## 4. Правило объединения

Объединять фразы, только если совпадают:

1. `core_entity`;
2. `intent`;
3. основная `customer_job`;
4. `solution_scope`;
5. `region_scope`, если предложение зависит от региона.

Контрольный вопрос: «Одна страница и один следующий шаг полностью удовлетворят обе формулировки?» Если нет — разделить.

### Разделять обязательно

- определение и покупку;
- готовое решение и самостоятельную разработку;
- продукт и обучение продукту;
- общий класс решения и конкретный бренд, если нужен отдельный ответ;
- B2B и B2C при разном предложении;
- разные города с отдельными ассортиментом, ценами или условиями;
- проблему и конкретную интеграцию, если у них разные посадочные.

### Допустимо объединять

- словоформы и порядок слов;
- русское и устойчивое английское название одной сущности;
- синонимы с одинаковым интентом;
- «как подключить» и «настройка», если процесс и целевая страница одинаковы.

## 5. Стабильный ID

Формировать при первом включении:

`{core_entity}__{intent}__{primary_job}`

Использовать lowercase ASCII slug. После создания не менять ID из-за новой канонической фразы. Старые названия сохранять в `aliases`.

При merge выбрать ID старшего или более бизнес-критичного кластера, остальные добавить в `merged_from`. При split сохранить исходный ID за основной веткой, новым веткам выдать новые ID. Всегда добавить событие в `change_log`.

## 6. Каноническая фраза

Выбирать по порядку:

1. однозначное соответствие продукту и интенту;
2. наибольший материальный объём;
3. естественная формулировка;
4. достаточная историческая серия;
5. отсутствие вложенного дубля.

Каноническая фраза служит меткой, а не заменяет список запросов кластера.

## 7. Контроль воспроизводимости

Два запуска на одном реестре и одном снимке Wordstat должны давать:

- одинаковый seed-manifest;
- одинаковые жёсткие решения forbidden/min-volume;
- те же cluster IDs для известных фраз;
- отдельный список новых и спорных кандидатов;
- объяснение каждого изменения.

Семантический `review` может требовать человеческого решения. Не скрывать эту неопределённость автоматическим включением.
