# Обзор библиотеки навыков

## Охват

По умолчанию проверять доступные личные навыки, учитывая системные и плагинные при поиске пересечений. Указать найдено / прочитано / недоступно и владельцев. Использовать доступный каталог, skills.list/skills.read с пагинацией либо предоставленный средой checkout. Не придумывать инструменты или скрытые журналы.

Сначала собрать метаданные, затем читать основные тексты небольшими группами. Вывод по одному description считать предварительным. Сходство названий не доказывает дублирование. Проверять назначение, аудиторию, входные данные, результат и зависимости; специализированный и общий навык могут дополнять друг друга.

Без истории провести статический аудит. Для анализа использования брать доступные журналы в области запроса; по умолчанию последние 30 дней, до 20 сессий при большой истории. Описать выборку и её ограничения. Не считать память о разговорах журналом вызовов. Не передавать историю сторонним сервисам; приводить минимальные обезличенные свидетельства. Не обещать локальную обработку на устройстве пользователя при работе в ChatGPT.

## Показатели

Различать наличие метаданных, чтение тела, применение и принятие результата. Чтение навыков самим аудитом не считать целевым использованием. Дедуплицировать события по навыку и сессии.

| Показатель | Расчёт и ограничение |
|---|---|
| Частота загрузки | Сессии с чтением тела / наблюдаемые сессии с данными о чтении |
| Частота применения | Сессии с подтверждённым применением / сессии, где применение наблюдаемо; отдельно применение среди загрузок |
| Нагрузка контекста | Токены реально зарегистрированных загрузок, если есть; отдельно измеренный размер текста как потенциальная нагрузка |
| Принятие результатов | Явно принятые / результаты с известным решением; отдельно число результатов без обратной связи |

Показывать период, числители и знаменатели. Нет событий в неполном экспорте — «нет данных», не ноль; нулевой знаменатель — «не применимо». Молчание пользователя не означает принятие. Не суммировать размер библиотеки как текущую стоимость контекста или оплаченные токены. При неизвестной версии навыка на момент события указать ограничение атрибуции.

## Решения

Для каждой рекомендации привести фрагмент файла либо сессию/сообщение и наблюдаемую проблему. Поведенческую причину отделять от гипотезы: сначала проверить релевантность задачи, доступность навыка и инструментов, а затем условия вызова. Ошибка всей сессии не доказывает дефект навыка.

Выбирать: оставить; уточнить description; сократить; вынести справку; объединить после проверки различий; рассмотреть отключение; собрать данные. Редкий аварийный навык может быть ценен. Не рекомендовать удаление только из-за размера или отсутствия наблюдений.

Начать с 3–5 существенных выводов, затем дать таблицу «Навык → свидетельство → проблема → действие → приоритет → уверенность». Показывать статистику использования только при наличии данных. Для главных исправлений дать «было → стало» и проверочный сценарий. Не присваивать псевдоточный суммарный балл здоровья.

Для повторного обзора сравнить с доступной базой, учитывая различия состава, периода и метода. Без предыдущего отчёта создать первый срез, не выдумывать динамику. Сохранять запрошенный отчёт по правилам среды. Не создавать расписание или скрытый сбор событий без запроса пользователя.
