# Правила решений v1.0

## CLIENT_STATE

| Статус | Достаточное основание |
|---|---|
| ACTIVE | Подтверждённое текущее сотрудничество, оплаченный проект, внедрение, обслуживание или другой действующий процесс |
| DORMANT | Подтверждённые прежние клиентские отношения; сейчас нет активного процесса/обязательств; нет окончательного отказа, исключающего контакт |
| LOST | Подтверждённое прекращение, отказ, выбор другого решения или иной завершённый отрицательный сценарий; активного процесса нет |
| COMPLETED | Прежняя работа завершена штатно, обязательства закрыты; текущего проекта нет |
| PROSPECT_ONLY | Контакт/возможность были, но покупка, выполненный проект или клиентские отношения не подтверждены |
| UNKNOWN | Недостаточно данных для надёжного текущего состояния |
| CONFLICT | Неразрешённые противоположные источники существенно влияют на текущее состояние |

Указать confidence и evidence. Состояние описывает фактические отношения, не разрешение контакта.

## REACTIVATION_ELIGIBILITY

YES разрешён только одновременно: не ACTIVE; нет активного процесса, обязательства или запрета; достаточно подтверждённой клиентской истории; нет нерешённого влияющего конфликта; gaps не мешают безопасному маршруту.

NO: ACTIVE/внедрение/обслуживание/другой действующий процесс; явное «не писать»; контакт уже ведёт сотрудник; PROSPECT_ONLY; нет основания для реактивации и не требуется интерпретация человека.

HUMAN_REVIEW имеет приоритет при неопределённом текущем процессе, специальных договорённостях, влияющем конфликте или неясном применении запрета. Человеческое указание сохранять как evidence; YES недопустим при запрете автоматического контакта. Если договорённость не позволяет выбрать внутренний маршрут — result, eligibility и routing = HUMAN_REVIEW. Не создавать автоматически задачу или сообщение человеку.

## Маршрутизация

| CLIENT_STATE | Eligibility | routing.next_process |
|---|---|---|
| ACTIVE | NO | ACTIVE_CLIENT |
| DORMANT / LOST / COMPLETED | YES | OPPORTUNITY |
| DORMANT / LOST / COMPLETED | NO | CLOSE |
| DORMANT / LOST / COMPLETED | HUMAN_REVIEW | HUMAN_REVIEW |
| PROSPECT_ONLY | NO | PROSPECT_SALES или CLOSE |
| UNKNOWN / CONFLICT | HUMAN_REVIEW | HUMAN_REVIEW |

REACTIVATION допустим вместо OPPORTUNITY только при YES и реально существующем отдельном процессе REACTIVATION. Не смешивать бизнес-цель реактивации с исследовательско-коммерческим Opportunity Loop. При Human Safety Gate с неясным маршрутом использовать HUMAN_REVIEW даже если отдельные факты указывают активность; не скрывать подтверждённую активность в отчёте.

## Причина прекращения и терминальный результат

stop_reason.status: CONFIRMED (прямое/сильное evidence причины), UNKNOWN (не доказана), CONFLICT (противоположные причины), NOT_APPLICABLE (пауза/прекращение не установлены или вопрос неприменим). Не выводить причину из молчания или предположения AI.

PASS: идентичность и история достаточны, состояние/eligibility/маршрут надёжны, существенные claims доказаны, последний контакт известен либо явно UNKNOWN, конфликты разрешены или не влияют, gaps перечислены.

PASS_WITH_GAPS: тот же надёжный основной вывод, но остаются только пробелы, не меняющие состояние, безопасность контакта или маршрут. Не использовать при критическом пробеле.

HUMAN_REVIEW: нужна интерпретация/решение человека из-за критической неопределённости, конфликта или договорённости; маршрут только HUMAN_REVIEW. Это не неудача исследования.

FAIL: исследование фактически не выполнило функцию — компания не идентифицирована, ключевые источники недоступны и практически нет истории, либо инфраструктура не позволяет продолжать. Не передавать в автоматический бизнес-процесс; зафиксировать routing.next_process=HUMAN_REVIEW как безопасную техническую остановку и объяснить FAIL.

Состояние, eligibility и терминальный result — разные поля. ACTIVE + NO + ACTIVE_CLIENT может иметь result PASS.
