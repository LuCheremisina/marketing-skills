# Versions, privacy and updates

Published releases are the distribution source. Skill packages exclude credentials, client profiles, closed datasets, transcripts, personal filesystem paths and internal installation logs. Methodologist attribution, source licenses and approved public author materials are intentional public credits. Synthetic examples are not measured client results.

Compare a last installed baseline, local content and upstream source using versions, source commits, file hashes, changelogs and behavior. File modification dates do not establish which version is newer. Preserve local modifications and resolve conflicts before updating. Third-party adaptation versions remain distinct from upstream versions.

Public upstream checks are scheduled monthly, on the first day at 00:00 Asia/Novosibirsk. The GitHub workflow checks public sources with read-only permissions and does not merge changes, publish releases or install packages. Updates require license, privacy and behavior review. A newer upstream version may appear between checks; the catalogue records the date of the last review.

Provider-managed plugins use provider update mechanisms. An older public mirror is not a reason to downgrade an installed provider package. Missing sources, changed license terms or conflicting modifications require review.

Compatibility statuses are `verified`, `requires_connection`, `not_verified` and `not_supported`. Package structure, native execution, publication and business outcomes are separate checks. Do not claim a verified runtime result from an archive or structural pass alone.
