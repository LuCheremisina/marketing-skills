## Содержание

- Фаза 1: SCOPE — Определение границ
- Фаза 2: PLAN — Формирование стратегии

- Декомпозиция запроса
- Протокол параллельного выполнения

- Стандарты качества источников
- Фаза 4: TRIANGULATE — Перекрёстная верификация

- Фаза 6: CRITIQUE — Контроль качества
- Фаза 7: REFINE — Итеративное улучшение

## Фаза 1: SCOPE — Определение границ

**Цель:** Определить границы исследования и критерии успеха

**Действия:**
1. Разбить вопрос на ключевые компоненты
2. Выявить точки зрения стейкхолдеров
3. Определить границы (что входит/не входит)
4. Установить критерии успеха
5. Перечислить допущения, требующие проверки

**Вывод:** Структурированный документ о границах исследования

---

## Фаза 2: PLAN — Формирование стратегии

**Цель:** Создать интеллектуальную дорожную карту исследования

**Действия:**
1. Определить первичные и вторичные источники
2. Карта зависимостей знаний (что нужно понять сначала)
3. Стратегия поисковых запросов с вариантами
4. Спланировать подход к триангуляции
5. Определить гейты качества

**Вывод:** План исследования с приоритизированными путями

---

## Фаза 3: RETRIEVE — Параллельный сбор данных

**Цель:** Систематически собирать информацию из множества источников параллельно

**КРИТИЧНО: Все поиски выполнять параллельно — одним сообщением с несколькими вызовами инструментов**

### Декомпозиция запроса

Перед поиском разбить исследовательский вопрос на 5–10 независимых углов:

1. **Основная тема (семантический поиск)** — базовый смысл концепции
2. **Технические детали (ключевые слова)** — термины, API, реализации
3. **Новые разработки (фильтр по дате)** — последние 12–18 месяцев
4. **Академические источники** — статьи, исследования, формальный анализ
5. **Альтернативные перспективы** — конкурирующие подходы, критика
6. **Статистика и данные** — количественные свидетельства, бенчмарки
7. **Отраслевой анализ** — коммерческие применения, рыночные тренды
8. **Критический анализ** — известные проблемы, граничные случаи

### Протокол параллельного выполнения

**Шаг 0: Получить текущую дату**
Перед ЛЮБЫМ поиском: `date +%Y-%m-%d` через Bash. Использовать год для всех запросов с фильтром по дате. НЕ использовать год из обучающих данных.

**Шаг 1: Запустить ВСЕ поиски одновременно**

**Основной инструмент: search-cli** (мульти-провайдер, использовать в первую очередь)
- Агрегирует Brave, Serper, Exa, Jina, Firecrawl
- JSON вывод: `search "запрос" --json`
- Режимы: general, news, academic, scholar, patents, people, images, extract, scrape
- Пример: `search "тема 2025" -m academic --json -c 15`
- Запускать через Bash: `search "запрос" --json -c 10`

**Резерв: WebSearch** (если search-cli недоступен или выдаёт ошибки)
- Поиск, предоставленный текущей платформой; проверить его наличие
- Параметры: `query` (обязательно), опционально `allowed_domains`, `blocked_domains`

**Опционально: Exa MCP** (если настроен, для семантического/нейронного поиска)
- Capability: `web.search` (точное имя инструмента определить в текущей платформе)

**Пример параллельного запуска (одно сообщение):**
```
- Bash: search "тема 2025 state of the art" --json -c 10
- Bash: search "тема ограничения проблемы" --json -c 10
- Bash: search "тема коммерческие применения" -m news --json -c 10
- Bash: search "тема vs альтернатива сравнение" --json -c 10
- Bash: search "тема исследования" -m academic --json -c 10
- Task(тип="general-purpose", описание="Анализ академических статей", запрос="Глубокий разбор академических работ по теме [ТЕКУЩИЙ ГОД]")
- Task(тип="general-purpose", описание="Отраслевой анализ", запрос="Анализ отраслевых отчётов и рыночных данных")
```

**Шаг 2: Запустить параллельных агентов** (3–5 агентов через Task)

Для: анализа академических статей, документации, репозиториев, специализированных исследований.

**Формат вывода субагентов** (требовать структурированные данные, не свободный текст):
```json
{"claim": "текст утверждения", "evidence_quote": "точная цитата из источника", "source_url": "https://...", "source_title": "...", "confidence": 0.85}
```

**Сохранение доказательств** (после каждой партии поиска сразу персистировать):
```bash
# Сначала зарегистрировать источник (возвращает стабильный source_id)
python scripts/citation_manager.py register-source --json '{"raw_url": "...", "title": "..."}' --dir [папка]

# Затем сохранить каждый фрагмент доказательства
python scripts/evidence_store.py add --json '{"source_id": "...", "quote": "точный текст", "evidence_type": "direct_quote", "locator": "стр. 5"}' --dir [папка]
```
Доказательства не должны существовать только в контексте модели — они должны быть персистированы в `evidence.jsonl` до начала синтеза.

**Шаг 3: Собрать и организовать результаты**

По мере поступления результатов:
1. Извлекать ключевые пассажи с метаданными источника (название, URL, дата, достоверность)
2. Фиксировать пробелы в знаниях
3. Следовать перспективным ответвлениям дополнительными целевыми поисками
4. Поддерживать разнообразие источников (академические, отраслевые, новостные, техдоки)

### Паттерн FFS (First Finish Search — первый достигший порога)

**Адаптивное завершение по порогу качества — переходить к Фазе 4 при достижении ПЕРВОГО из условий:**

| Режим | Порог источников | Макс. время |
|-------|-----------------|-------------|
| Quick | 10+ (достоверность >60/100) | 2 мин |
| Standard | 15+ (достоверность >60/100) | 5 мин |
| Deep | 25+ (достоверность >70/100) | 10 мин |
| UltraDeep | 30+ (достоверность >75/100) | 15 мин |

Если порог достигнут рано — продолжать оставшиеся поиски в фоне. Дополнительные источники используются в Фазе 5.

### Стандарты качества источников

- Минимум 3 типа источников (академические, отраслевые, новостные, техдоки)
- Временное разнообразие (последние 12–18 мес. + фундаментальные старые)
- Разнообразие перспектив (сторонники + критики + нейтральный анализ)
- Географическое разнообразие (не только US-источники)
- Оценка достоверности каждого источника 0–100 через source_evaluator.py

**Вывод:** Организованный репозиторий с отслеживанием источников, оценками достоверности и картой покрытия

## Фаза 4: TRIANGULATE — Перекрёстная верификация

**Цель:** Проверить информацию по нескольким независимым источникам

**Действия:**
1. Выявить утверждения, требующие верификации
2. Перекрёстные ссылки фактов по 3+ источникам
3. Отметить противоречия или неопределённости
4. Оценить достоверность источников
5. Зафиксировать области консенсуса vs дискуссии
6. Задокументировать статус верификации по каждому утверждению

**Стандарты:** Ключевые утверждения должны иметь 3+ независимых источника. Отмечать информацию из единственного источника. Указывать актуальность информации. Выявлять потенциальные предвзятости.

**Вывод:** Верифицированная база фактов с уровнями достоверности

## Фаза 4.5: OUTLINE REFINEMENT — Динамическая адаптация структуры

**Цель:** Адаптировать направление исследования на основе найденных доказательств

**Когда выполнять:** Только в режимах Standard/Deep/UltraDeep (Quick пропускает). После Фазы 4, перед Фазой 5.

**Действия:**

1. **Сравнить начальный охват с реальными находками**
   - Сравнить Фазу 1 с открытиями Фаз 3–4
   - Выявить неожиданные паттерны или противоречия
   - Отметить недостаточно исследованные углы, ставшие критическими

2. **Оценить необходимость адаптации**

   **Сигналы для адаптации (любой из них → уточнить):**
   - Ключевые находки противоречат начальным допущениям
   - Доказательства выявили более важный угол, чем запланировано
   - Появилась критическая подтема, не учтённая в плане
   - Исходный вопрос оказался слишком широким/узким

   **Сигналы оставить структуру:**
   - Доказательства соответствуют исходному охвату
   - Все ключевые углы достаточно покрыты

3. **Уточнить структуру (при необходимости)**
   - Добавить разделы для неожиданных, но важных находок
   - Понизить/удалить разделы с недостаточными доказательствами
   - Переупорядочить по силе доказательств и важности
   - Адаптация основана исключительно на доказательствах, не на спекуляции

4. **Целевое заполнение пробелов** (только если выявлены критические пробелы)
   - 2–3 целевых поиска по новым углам
   - Только быстрый поиск (не перезапускать Фазу 3)
   - Ограничить 2–5 минутами

5. **Задокументировать обоснование адаптации** в приложении Методологии

**Стандарты качества:**
- Адаптация должна быть обоснована доказательствами (цитировать конкретные источники)
- Не более 50% реструктуризации структуры
- Сохранять основной исследовательский вопрос (не уходить в другую тему)
- Новые разделы должны иметь уже собранные доказательства

**Антипаттерны:**
- ❌ Адаптировать структуру из соображений "что было бы интересно"
- ❌ Добавлять разделы без доказательств на руках
- ❌ Полностью отказываться от исходного вопроса
- ✅ Адаптировать когда доказательства явно указывают на лучшую структуру

**Вывод:** Уточнённая структура, отражающая реальный ландшафт доказательств

## Фаза 5: SYNTHESIZE — Глубокий анализ

**Цель:** Соединить инсайты и выработать новое понимание

**Действия:**
1. Выявить паттерны в источниках
2. Карта отношений между концепциями
3. Генерировать инсайты за пределами исходного материала
4. Создавать концептуальные фреймворки
5. Строить структуры аргументов
6. Развивать иерархии доказательств

Использовать расширенное рассуждение для поиска неочевидных связей и импликаций второго порядка.

**Вывод:** Синтезированное понимание с генерацией инсайтов

---

## Фаза 6: CRITIQUE — Контроль качества

**Цель:** Строго оценить качество исследования

**Действия:**
1. Проверить логическую последовательность
2. Проверить полноту ссылок
3. Выявить пробелы или слабые места
4. Оценить сбалансированность и объективность
5. Верифицировать утверждения по источникам
6. Проверить альтернативные интерпретации

**Вопросы красной команды:**
- Чего не хватает?
- Что может быть неверным?
- Какие альтернативные объяснения существуют?
- Какие предвзятости могут присутствовать?
- Какие контрфактуалы стоит рассмотреть?

**Ролевая критика** (только Deep/UltraDeep):
Симулировать 2–3 конкретных персонажа критика:
- "Скептичный практик" — доверился бы этим выводам тот, кто делает это ежедневно?
- "Враждебный рецензент" — что отверг бы рецензент?
- "Инженер внедрения" — можно ли реально реализовать рекомендации?

**Петля возврата при критическом пробеле:**
Если критика выявила критический пробел в знаниях — вернуться к Фазе 3 с целевыми "дельта-запросами" (не просто редакционная правка). Ограничить 3–5 мин.

**Вывод:** Отчёт о критике с рекомендациями по улучшению

---

## Фаза 7: REFINE — Итеративное улучшение

**Цель:** Устранить пробелы и усилить слабые места

**Действия:**
1. Провести дополнительные исследования для пробелов
2. Укрепить слабые аргументы
3. Добавить недостающие перспективы
4. Разрешить противоречия
5. Улучшить ясность

**Вывод:** Усиленное исследование с устранёнными недостатками

---

## Фаза 8: PACKAGE — Генерация отчёта

Подробные инструкции — в [report-assembly.md](./report-assembly.md).

**Цель:** Создать профессиональный, применимый отчёт

**Кратко:** Прогрессивная генерация по разделам (Write/Edit), каждый вызов ≤2000 слов. Регистрировать источники через citation_manager.py. Запустить validate_report.py и verify_citations.py после завершения.

**Вывод:** Полный отчёт, готовый к использованию
