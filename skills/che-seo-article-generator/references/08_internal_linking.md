# Internal Linking

## Входные данные

- `entity_seo_article.md`
- `inputs/site_links.txt` — список URL сайта. **Основной источник кандидатов.**
- focus_keyword, secondary_keywords из Semantic Skill
- SITE_URL из `inputs/config.txt`

## Выходные данные

- `article_with_links.md` — только ссылки, прошедшие HTTP-верификацию.

---

## ⛔ ЖЁСТКИЕ ПРАВИЛА

### Правило 1 — Только из списка

Все URL — исключительно из `inputs/site_links.txt` или живого поиска по сайту.
Придуманные из памяти URL — запрещены: slug из текста статьи почти всегда содержит опечатки или кириллицу.

### Правило 2 — HTTP-верификация через curl

Каждую ссылку проверить до включения:

```bash
curl -s -o /dev/null -w "%{http_code}" -L --max-redirs 5 --connect-timeout 8 "URL"
```

| Код | Действие |
|---|---|
| 200, 403 | ✅ включить |
| 301, 302 | ✅ включить конечный URL (флаг `-L` следует) |
| 404, 5xx | ❌ заменить другим кандидатом |
| 0 / timeout | ❌ удалить, не ждать повтора |

**Код 502** — не «временная ошибка»: slug содержит невидимый не-ASCII символ. Заменить.

### Правило 3 — Проверка slug (только Latin + дефисы)

```bash
echo "URL" | grep -P '[^\x00-\x7F]'
# Непустой вывод = запрещённые символы → ссылку не использовать
```

### Правило 4 — Нет замены = нет ссылки

Лучше 4 рабочие ссылки, чем 5 с одной битой.

### Правило 5 — Блокировка

Pipeline не переходит к этапу 9, пока:
- [ ] Все ссылки прошли curl (200 или 403)
- [ ] Ни один slug не содержит не-ASCII символов
- [ ] Нет self-ссылок на текущую статью

---

## Логика работы

1. Прочитать `inputs/site_links.txt`. Отобрать 8–10 тематически близких URL.
2. Проверить каждый на не-ASCII в slug — исключить нарушителей.
3. Batch curl-проверка оставшихся кандидатов:
   ```bash
   for url in URL1 URL2 URL3; do
     code=$(curl -s -o /dev/null -w "%{http_code}" -L --max-redirs 5 --connect-timeout 8 "$url")
     echo "$code | $url"
   done
   ```
4. Из рабочих выбрать 5–6 наиболее релевантных (3 блог + 2 глоссарий/услуги).
5. Встроить в тематически релевантных местах — не скучивать в одном абзаце.
6. Вывести итоговый список URL + HTTP-коды перед сохранением.
7. Сохранить в `article_with_links.md`.
