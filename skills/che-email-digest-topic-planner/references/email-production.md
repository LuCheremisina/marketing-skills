# Редакционные и HTML-правила email

Ссылки пользователя — источник истины, сохранять destination URL. Для каждой
темы: тезис, изменение/проблема, значение для аудитории, практический вывод,
подтверждённые факты/ограничения. Одна ось отвечает «что читатель поймёт» и задаёт
тему, прехедер, вводную, порядок и CTA. Главная тема → практическое следствие →
доказательство → следующий шаг. Не пересказывать весь источник.

Вводная 2–4 предложения (ориентир 40–80 слов); карточка 60–110 слов. Объём
подчинён пользе, не формальному лимиту. Тема конкретная без кликбейта; прехедер
добавляет смысл. Информационный баланс 80% ценности/20% перехода — ориентир,
не обязательное коммерческое обещание. События/продукты отделять от статей;
два CTA только для действительно разных задач из входа. Не выдумывать даты,
цены, места, срочность, кейсы и гарантии.

Голос и личная подпись — только из пользовательского профиля. Не писать от лица
методолога, не навязывать личный бренд/палитру/портрет. Без профиля запросить его
либо явно согласовать нейтральный черновик. Профиль: brand_name, brand_url,
sender_name, voice, font_family, colors с ролями background/paper/text/paragraph/
muted/accent/dark/light; CTA и подпись. Можно добавить action_background.

Шаблон — структурная основа с параметрами, а не фиксированный визуальный бренд.
Табличная email-вёрстка, inline styles, 600 px responsive width, системный
fallback; без JS, Grid/Flex. Скрытый прехедер; все брендовые ссылки кликабельны.
Карточка: номер, конкретный URL, заголовок, текст, короткий CTA. Изображение
только если разрешён URL; ссылкой на материал, alt, width:100%, height:auto.
Не добавлять пустой блок или сторонний портрет. Системную отписку брать только
из подтверждённого механизма отправляющей платформы; не выдумывать macro.

Полный HTML не содержит {{...}}, TODO, сокращений, тестовых URL или Markdown.
Тема/прехедер сохраняются отдельно; .html не заменяет код, если запрошен код.
Подготовка письма не разрешает отправку, запись, тестовое письмо или рассылку.
