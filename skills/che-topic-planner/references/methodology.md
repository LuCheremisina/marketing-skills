## Пороги отбора

| Метрика | Порог по умолчанию | Ниже порога |
|---|---|---|
| Спрос, регион 1 | ≥ 500 запросов/мес | → соцсети / email |
| Спрос, регион 2 | ≥ 100 запросов/мес | → соцсети / email |
| Окно актуальности | ≤ 20 дней | → откладывать или переформатировать |

Сезонные темы (учёба, праздники, отпускной сезон и т.п.) — исключение: окно
актуальности расширяется до 60 дней при условии пикового сезонного спроса.

Для B2B и услуг с низкочастотным спросом дефолтные пороги почти всегда
завышены — фактические цифры берутся из `config.regions`, а не из этой
таблицы.

## Типы контента — дефолтный набор

Подходит для e-commerce и товарных каталогов. Если ниша другая —
адаптировать номенклатуру при онбординге (см. раздел «Первый запуск» в
SKILL.md) и описать новые типы по той же структуре.

### 1. Обзор позиции
- Когда: новинка в каталоге, старт продаж ≤ окна актуальности
- Структура: характеристики/детали → жизненные сценарии → кому подходит → CTA
- Запросы для проверки спроса: `[позиция] обзор`, `[позиция] купить`, `[позиция] цена`

### 2. Сравнение
- Когда: обе позиции в каталоге, аудитория активно выбирает между ними
- Структура: краткие итоги → таблица сравнения → сценарии → вывод по типу покупателя
- Запросы: `[А] vs [Б]`, `что лучше [А] или [Б]`

### 3. Сценарный гайд
- Когда: аудитория ещё не выбрала позицию, ищет «X для задачи Y»
- Структура: описание задачи → критерии выбора → топ-3/5 по бюджету или сегменту → CTA
- Запросы: `[категория] для [задача]`, `лучший [категория] до N рублей`

### 4. Трендовый материал
- Когда: значимый инфоповод в нише + релевантные позиции каталога
- Структура: тренд → что это значит для аудитории → конкретные позиции
- Запросы: `[тренд] [год]`
- AI-видимость (GEO): высокая — такие материалы чаще попадают в AI-ответы

## Альтернативные типы контента (примеры для других ниш)

| Ниша | Тип контента | Когда использовать |
|---|---|---|
| B2B / услуги | Кейс | Есть измеримый результат клиента, можно назвать цифры |
| B2B / услуги | Экспертное мнение | Инфоповод в отрасли требует позиции компании |
| SaaS | Инструкция | Частый вопрос в поддержке = частый поисковый запрос |
| Любая ниша | FAQ-материал | Несколько похожих вопросов от аудитории/клиентов |
| Недвижимость | Гайд по району/проекту | Сезонный или ситуативный спрос на локацию |

## Углы подачи по сегменту аудитории — пример структуры

Заполняется в `config.audience_segments` при онбординге. Пример (e-commerce,
электроника):

| Сегмент | Угол | Пример заголовка |
|---|---|---|
| Семьи | Надёжность, простота, поддержка | «Что выбрать для всей семьи в 2026» |
| Прагматики | Цена, функциональность, долговечность | «[Позиция] за N рублей: что получаешь на самом деле» |
| Энтузиасты | Детальное сравнение, честные компромиссы | «[A] vs [B]: честное сравнение без маркетинга» |
| Бизнес | Надёжность, скорость выбора, сервис | «[Позиция] для работы: что важно знать до покупки» |
| Охотники за выгодой | Альтернатива дорогому варианту | «Лучшая альтернатива [дорогой]: [X] в 2026» |

## Матрица приоритизации

```
                    Спрос высокий       Спрос низкий
Инфоповод ≤ окна   🔴 СРОЧНО           🟡 Соцсети сейчас
Инфоповод > окна   🟠 ВАЖНО            🟢 Следующий квартал
Сезонный пик       🟠 ВАЖНО            🟡 Планово
```

## Конкурентная среда

При формулировке угла проверять, что пишут конкуренты из `config.competitors`.

Если тема плохо закрыта конкурентами → приоритет выше.
Если тема перегружена → искать нишевый угол (регион, сценарий, сегмент,
ценовая категория).

## Редполитика — как использовать config.redpolicy

`forbidden_topics` — темы, которые не предлагать вообще, даже под другим
углом, если сама структура темы работает против интересов клиента (пример
из практики: сравнение параллельного импорта и официальной версии товара —
структура темы сама подталкивает читателя считать один из вариантов
«неправильным», даже при нейтральной формулировке).

`forbidden_phrases` — конкретные формулировки и слова, которых не должно быть
в заголовках и углах подачи.

`cta_target` — единственное место, куда ведут все призывы к действию.

Если в проекте задан запрет на упоминание цен или площадок конкурентов
(маркетплейсы, агрегаторы) — фиксировать это явно в `redpolicy` при
онбординге, не предполагать по умолчанию.

## Проверка спроса — практические советы

Для каждой темы проверять в порядке убывания приоритета:
1. `[позиция] обзор` / `[позиция] что это` — информационный спрос
2. `[позиция] купить` / `[позиция] заказать` — коммерческий спрос (выше
   приоритет для конверсии)
3. `[позиция] характеристики` / `[позиция] условия` — дополнительный трафик
4. `[позиция] цена` / `[позиция] стоимость` — охотники за выгодой

Регион: сначала основной (`config.regions[0]`), потом локальный/нишевый.
Сезонность: если у запроса есть предсказуемый пик — планировать материал за
3–4 недели до пика.
