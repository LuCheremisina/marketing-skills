## Требования к объёму по режимам

| Режим | Целевой объём | Описание |
|-------|--------------|---------|
| Quick | 2000–4000 слов | Базовый порог качества |
| Standard | 4000–8000 слов | Комплексный анализ |
| Deep | 8000–15000 слов | Тщательное исследование |
| UltraDeep | 15000–20000+ слов | Максимальная строгость |

## Защита от переполнения вывода

**Лимит выходных токенов хоста по умолчанию:** 32 000 (~24 000 слов на выполнение)

**Практические ограничения:**
- Целевой максимум ≤20 000 слов общего вывода
- Оставлять запас для накладных расходов на вызовы инструментов
- Отчёты >20 000 слов требуют автопродолжения (см. continuation.md)

## Прогрессивная генерация разделов

**Основная стратегия:** Генерировать и записывать каждый раздел по отдельности через Write/Edit. Это позволяет создавать отчёты неограниченной длины при сохранении управляемости каждой генерации.

### Фаза 8.1: Подготовка

```bash
# Каталог задаёт RESEARCH_OUTPUT_DIR; иначе ./research_output
mkdir -p "${RESEARCH_OUTPUT_DIR:-./research_output}/[НазваниеТемы]_Research_[YYYYMMDD]/"

# Путь к файлу: [папка]/research_report_[YYYYMMDD]_[slug].md
```

### Фаза 8.2: Цикл генерации разделов

**Паттерн:** Сгенерировать раздел → Записать/отредактировать файл → Перейти к следующему
Каждый вызов Write/Edit содержит ОДИН раздел (≤2000 слов на вызов)

**Инициализация исследовательского запуска:**
```bash
python scripts/citation_manager.py init-run --out-dir [папка] --query "[вопрос]" --mode [режим]
# Создаёт: run_manifest.json, sources.jsonl, evidence.jsonl, claims.jsonl
```

**Регистрировать каждый источник при обнаружении:**
```bash
python scripts/citation_manager.py register-source \
  --json '{"raw_url": "...", "title": "...", "source_type": "academic", "year": "2024"}' \
  --dir [папка]
# Возвращает стабильный source_id (на основе sha256, сохраняется при перенумерации и продолжении)
```

**Присваивать отображаемые номера после регистрации всех источников:**
```bash
python scripts/citation_manager.py assign-display-numbers --dir [папка]
# Сопоставляет стабильные source_ids с [1], [2], [3]... для рендеринга
```

Идентичность источника стабильна при редактировании и продолжении. Отображаемые номера выводятся при рендеринге, не хранятся в состоянии. Это работает при сжатии контекста и позволяет агентам продолжения получить состояние ссылок через стабильные ID.

**Последовательность разделов:**

1. **Executive Summary** (200–400 слов)
   - Инструмент: Write(файл, frontmatter + Executive Summary)
   - Отслеживать ссылки
   - Прогресс: "Executive Summary завершён"

2. **Введение** (400–800 слов)
   - Инструмент: Edit(файл, добавить Введение)
   - Отслеживать ссылки
   - Прогресс: "Введение завершено"

3. **Вывод 1–N** (600–2000 слов каждый)
   - Инструмент: Edit(файл, добавить Вывод N)
   - Отслеживать ссылки
   - Прогресс: "Вывод N завершён"

4. **Синтез и инсайты**
   - Новые инсайты за пределами утверждений источников
   - Инструмент: Edit(добавить)

5. **Ограничения и оговорки**
   - Контрдоказательства, пробелы, неопределённости
   - Инструмент: Edit(добавить)

6. **Рекомендации**
   - Немедленные действия, следующие шаги, потребности в исследованиях
   - Инструмент: Edit(добавить)

7. **Библиография** (КРИТИЧНО)
   - КАЖДАЯ ссылка из списка использованных
   - НЕТ диапазонам, НЕТ плейсхолдерам, НЕТ обрезанию
   - Инструмент: Edit(добавить)

8. **Приложение: Методология**
   - Исследовательский процесс, подход к верификации
   - Инструмент: Edit(добавить)

## Организация файлов

**1. Создать выделенную папку:**
- Расположение: `${RESEARCH_OUTPUT_DIR:-./research_output}/[НазваниеТемы]_Research_[YYYYMMDD]/`
- Чистое название темы (убрать спецсимволы, использовать подчёркивания)

**2. Конвенция именования файлов:**
Все файлы используют одно базовое имя:
- `research_report_20251104_topic_slug.md`
- `research_report_20251104_topic_slug.html`
- `research_report_20251104_topic_slug.pdf`

**3. Дополнительно сохранить копию в:** `${RESEARCH_OUTPUT_DIR:-./research_output}/research_output/` (внутреннее отслеживание)

## Число слов на раздел

**КРИТИЧНО:** Ни один вызов Edit не должен превышать 2000 слов.

Пример: 10 выводов × 1500 слов = 15 000 слов итого
- Каждый вызов Edit: 1500 слов (в пределах лимита)
- Файл вырастает до 15 000 слов
- Ни один вызов инструмента не превышает лимиты
