## Режимы

### interactive

Использовать MCP для структурированных данных и записи. Browser использовать для:

- link map в UniSender, если MCP её не даёт;
- чтения прошлых писем и проверки повторов;
- поиска существующего черновика;
- desktop/mobile preview;
- проверки изображений, отправителя, списка и системной отписки.

Browser работает в отдельном профиле. При входе передать управление пользователю. Не просить пароль или код в чате.

### scheduled

Не использовать Browser как скрытый fallback. При отсутствии link map вернуть `partial`. Создавать черновик только при наличии устойчивой проверки дублей или состояния запуска.

### dry_run

Не выполнять внешние записи. Разрешены read-only MCP, web, расчёты, HTML и локальная QA.

## Поиск MCP-возможностей

Сопоставлять инструменты по назначению:

- UniSender list campaigns / common stats / delivery stats / create email message;
- Wordstat top requests / dynamics / regions tree;
- Метрика report data по UTM;
- amoCRM leads/deals, fields, pipelines, statuses, amount.

Не считать отсутствие метода в первоначальном списке доказательством отсутствия коннектора. Выполнить доступное обнаружение инструментов. Если нужная возможность всё равно не найдена, назвать конкретный пробел.

## Browser link map

Собирать только видимые данные:

- campaign ID/subject/date;
- URL;
- текст или роль элемента;
- положение;
- all clicks;
- unique clickers, только если явно обозначены.

Не вычислять unique clickers из all clicks. Зафиксировать время просмотра. При пагинации пройти весь релевантный набор или явно указать охват.

Если интерфейс изменился, не делать догадки по координатам. Остановить browser-часть, сохранить остальной результат как `partial`.

## Создание черновика

Целевое действие — UniSender `createEmailMessage` или эквивалентное создание сообщения без кампании.

Перед вызовом подтвердить:

- list ID из подтверждённого профиля;
- subject;
- полный HTML;
- успешный validator;
- отсутствие существующего draft key;
- sender задан пользователем или настроен в аккаунте.

После вызова сохранить `message_id`. Не вызывать создание/запуск кампании. Не отправлять тестовое письмо без новой отдельной команды.

Browser допускается как резервный путь создания черновика только в ручном запуске поддерживающей среды, если MCP-create недоступен и пользователь явно попросил довести создание до конца. Заполнять одну форму, сохранить как черновик, проверить статус и остановиться.

## Идемпотентность

Использовать:

`draft_key = digest:<YYYY-MM-DD>:<topic-slug>`.

Правила:

1. Один create на один подтверждённый запуск.
2. Перед create искать совпадение по draft key, теме и дате.
3. После успешного create сохранять message ID в доступном состоянии задачи.
4. После timeout не повторять create автоматически.
5. Сначала проверить UI/список сообщений.
6. Если результат не определён, вернуть `unknown` и остановиться.

## Разрешения

Запрос на «подготовить письмо» не равен запросу создать внешний черновик. Внешнюю запись выполнять, когда пользователь:

- прямо просит создать/сформировать черновик в UniSender; или
- явно запускает этот end-to-end Skill с ожидаемым результатом «черновик UniSender».

Запрос на анализ, отчёт, HTML или dry-run не разрешает запись.

Никогда не изменять контакты, списки, кампании, расписание или отправку без отдельного явного запроса.

## Ошибки и деградация

- Временная read-only ошибка: повторить ограниченно, затем `partial`.
- Ошибка Wordstat или исчерпанная квота: не подставлять качественную оценку как фактическую частотность; `topic_radar=partial`, `wordstat=partial/missing`, demand score оставить `null`.
- Ошибка amoCRM-полей: не приписывать заявки кампании, `crm=partial`.
- Нет link map: `link_stats=partial/missing`.
- Ошибка HTML/UTM: `blocked`, черновик не создавать.
- Неоднозначная ошибка create: `draft=unknown`, не повторять.
- Требуется login: остановиться и предложить ручной вход.

Никогда не выдавать неполный аудит за полный и не скрывать источник ограничения.
