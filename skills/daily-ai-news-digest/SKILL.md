# Daily AI News Digest

Подготовить ежедневную русскоязычную сводку AI-новостей для Telegram. Код
выполняет сбор, фильтрацию, дедупликацию, обогащение, HTML-сборку и доставку;
основные инструкции здесь определяют безопасный запуск и блокирующие проверки.
История версий находится в [references/CHANGELOG.md](references/CHANGELOG.md),
источники — в [references/sources.md](references/sources.md).

## Режим

- Ручной запрос на проверку или подготовку → `DRY_RUN=1`.
- Отправка разрешена только прямой командой пользователя либо ранее созданной
  задачей, которая явно включает доставку подписчикам.
- Не создавать и не запускать расписание только потому, что оно описано в Skill.

Не выводить токены, ключи и идентификаторы подписчиков. Не очищать историю для
получения большего числа новостей: это разрушает дедупликацию.

## Контракт зависимостей и запуск

Требуются Python-пакеты `openai`, `feedparser`, `requests`, capability
`llm.generate` и, только для доставки, `telegram.message.send`. Способ
подключения и авторизации определяет платформа; Skill не запрашивает и не
сохраняет секреты. Runtime может настроить `MAX_NEWS`, `MIN_NEWS`, часовой пояс
и безопасный dry-run.

Безопасная проверка:

```bash
DRY_RUN=1 python3 scripts/collect_and_send.py
```

Авторизованный запуск доставки:

```bash
python3 scripts/collect_and_send.py
```

`collect_and_send.py` запускает `bot_subscribe.py` только вне dry-run.
Подписчики управляют состоянием через `/start`, `/stop`, `/status`.

## Конвейер

1. Загрузить историю отправленных событий.
2. Собрать RSS и отделить публикацию материала от даты события.
3. Удалить междневные и внутридневные дубли одного события.
4. Исключить военно-политические, инвестиционные и иные запрещённые темы.
5. Ранжировать по свежести, подтверждённости и бизнес-влиянию.
6. Для каждой новости сохранить один прямой источник, точный статус события,
   краткое описание и конкретное бизнес-следствие.
7. Сформировать полный HTML и выполнить блокирующую проверку.
8. В dry-run сохранить диагностический результат без доставки. В
   разрешённом режиме отправить только прошедший проверку выпуск и затем
   обновить историю.

Не добивать выпуск повторами или заглушками. Если после фильтрации меньше
`MIN_NEWS`, закончить со статусом `warn`; если готовый текст или HTML нарушает
контракт, закончить со статусом `blocked`.

## Блокирующая проверка

Перед отправкой код обязан подтвердить:

- число новостей от `MIN_NEWS` до `MAX_NEWS`;
- одна прямая HTTP(S)-ссылка на каждую новость;
- число HTML-карточек совпадает с числом новостей;
- полный HTML с doctype и закрывающим тегом;
- отсутствие placeholders, тестовых URL и незавершённых значений.

Дополнительно применить критерии из `evals/shared.csv` и
`evals/skill-specific.csv` по `evals/judge_prompt.md`: дата события, окно,
первоисточник, точный статус анонса/релиза, отсутствие дублей и усилений фактов,
бизнес-значимость и порядок приоритетов. Если обязательный критерий нельзя
подтвердить, исключить новость или заблокировать отправку. Не считать LLM-фразу
«проверено» доказательством.

## Результат

Сообщить статус `dry_run`, `ok`, `warn`, `blocked` или `error`, число новостей,
покрытие источников, причины исключений и результат доставки. Для `blocked`
перечислить конкретные нарушения. Не утверждать, что письмо доставлено всем,
если доступен только общий успех запроса без результата по получателям.

## Переносимость и запуск

Пути к ресурсам ниже относительны корню установленного навыка. Перед запуском
определи этот корень через механизм платформы; не предполагай текущую папку.
Относительные примеры CLI разрешай в абсолютный путь к скрипту, сохраняя рабочую
папку результата отдельно. Переменные и механизмы конкретной платформы задаются
её адаптером, не являются зависимостью универсальной методологии. Без Python, сети или коннектора запросить нормализованный вход или
вернуть ограниченный результат с явным статусом «не проверено».

Здесь capability обозначает возможность, а не гарантированное имя MCP-команды.
Вызовы в примерах — схема: сначала прочитать объявленные инструменты и сопоставить
аргументы. Не устанавливать зависимости, не создавать расписания, не публиковать
и не отправлять сообщения без применимого разрешения пользователя.

Runtime-подписчики и история находятся вне пакета: `DIGEST_DATA_DIR`, по умолчанию
`~/.local/share/daily-ai-news-digest`. Для подготовки `DRY_RUN=1`; получение
новостей и LLM-проверка всё ещё требуют соответствующих подключений.
