## Основание

Конвейер сохраняет источник, статус утверждений и смысл при переходе от письменной новости к устной речи. Длительность и темп определяются профилем рассказчика; частные наблюдения первоначального проекта исключены.

## Что воспроизводить

Текущая озвучка — не конспект по разделам. Она перестраивает материал в одну устную причинно-следственную линию:

`событие → бизнес-сдвиг → три опоры → действие → короткий вывод`.

Повторяющиеся элементы во всей выборке:

- обещание короткого формата или быстрый вход в тему;
- сильный тезис в первых 2–3 предложениях;
- три смысловых блока с устными переходами;
- прямое обращение к слушателю;
- одна ведущая бытовая метафора;
- практический тест или следующий шаг;
- афористичный финал;
- отдельный AI-дисклеймер.

Типовой смысл трёх блоков:

1. Что изменилось по сравнению со старым способом.
2. Как работает новый механизм и где его важное ограничение.
3. Что проверить в бизнесе и какую роль оставить человеку.

## Как отбирать материал

Сохраняй:

- центральный факт события;
- один механизм, без которого новость нельзя понять;
- бизнес-последствие;
- один выразительный факт или число;
- одну критическую оговорку;
- один тест, метрику или следующий шаг из статьи;
- роль человека там, где действие имеет последствия.

Сокращай или исключай:

- длинные каталоги функций и интеграций;
- повторения между лидом, «Коротко» и основными разделами;
- второстепенные примеры;
- таблицы как таблицы — забирай только один нужный вывод;
- навигацию, ссылки, CTA, related-блоки;
- числа, которые не меняют управленческий вывод.

Не исключай оговорку ради динамики. Если тезис основан на внутреннем эксперименте одной компании, это должно прозвучать рядом с результатом. Если функция в пилоте, нельзя называть её общедоступной. Если источник говорит `до 50%`, сценарий не может говорить `на 50%`.

## Драматургия для слуха

Вступление должно ответить на два вопроса: что произошло и почему слушателю стоит продолжить. Избегай пустого «сегодня поговорим».

Каждый из трёх блоков строится по простой схеме:

`тезис → короткое объяснение → практическое следствие`.

Риторический вопрос полезен как мост между блоками, но не должен заменять аргумент. Норма выборки — до трёх вопросов на выпуск.

Метафора должна упрощать форму, а не менять факты. Хорошая метафора помогает запомнить механизм. Плохая добавляет несуществующую гарантию: например, образ «вы дали агенту кредитную карту» противоречит новости, если платёжные реквизиты агенту не видны.

Финал не пересказывает весь текст. Он связывает событие с одним решением слушателя на этой неделе.

## Протокол чисел и терминов

Перед черновиком создай внутреннюю запись для каждого числа:

| Поле | Пример |
|---|---|
| Значение | 61 008 |
| Единица | публикаций |
| Знаменатель / база | после очистки выборки |
| Тип статистики | размер выборки / медиана / перцентиль |
| Субъект | данные одного сервиса |
| Квалификатор | примерно / до / более |
| Ограничение | корреляция, не причинность |

В речи число можно округлить только если управленческий смысл и тип статистики не меняются. После округления оговорка остаётся.

Технический термин можно объяснить бытовым языком, но не переименовывать. Например: `кэш промпта — сохранённый повторно используемый префикс`, а не `память нейросети`.

## Граница доказательности

По наблюдаемым парам можно уверенно восстановить устойчивую редакционную форму. Нельзя доказать точный исходный промпт NotebookLM: он не был доступен. Поэтому skill воспроизводит подтверждённые паттерны результата, а не заявляет реконструкцию скрытых настроек сервиса.
