# Методология аудита

## 1. Уровни уверенности по выборке

- 8–10 сопоставимых primary-кампаний: диагностический baseline, выводы предварительные.
- 25–30: рабочая база для устойчивых паттернов темы, структуры и CTA.
- 40–50: более надёжное сравнение сегментов, форматов и размещений.
- 60+: многофакторный анализ при достаточном числе событий.

Оценивать не только число кампаний, но и число доставленных писем, уникальных кликающих, визитов и заявок. Кампании не являются полностью независимыми наблюдениями, если значительная часть подписчиков повторяется.

## 2. Зрелость данных

Использовать единые окна:

- D+1: ранний сигнал, не включать в финальный baseline;
- D+3: оперативный срез `provisional`;
- D+7: основной финальный срез;
- D+14: дополнительный срез только при доказанном длинном цикле конверсии.

Не сравнивать lifetime старого письма с D+1 нового. Для основного baseline использовать только D+7.

## 3. Сопоставимость primary-кампаний

Включать кампанию в основной baseline, если:

- это первичная отправка;
- окно наблюдения совпадает;
- аудитория и назначение письма сопоставимы;
- статистика не является тестовой или технической;
- ключевые метрики доступны;
- нет существенного инцидента доставки или трекинга.

Не удалять аномалии молча. Показывать baseline с аномалиями и при необходимости чувствительность без них.

## 4. Повторы по неоткрывшим

Анализировать resend отдельно. Не включать в primary baseline и не трактовать как чистый A/B-тест темы: различаются аудитория, время и предшествующий контакт.

Считать:

- дополнительные уникальные открытия и кликающих;
- дополнительные визиты и заявки;
- отписки и жалобы;
- инкремент на 1,000 первоначально доставленных;
- суммарный результат связки original + resend с дедупликацией, если она доступна.

Фиксировать `resend_dedup` отдельно. Если дедупликация недоступна, не рассчитывать суммарный уникальный результат пары и пометить соответствующий источник как `partial` или `missing`.

Для устойчивого решения о resend-стратегии желательно 8–10 сопоставимых пар.

## 5. Формулы

- `delivery_rate = delivered / sent`.
- `open_rate = unique_opens / delivered`.
- `ctr = unique_clickers / delivered`.
- `ctor = unique_clickers / unique_opens`.
- `unsubscribe_rate = unsubscribes / delivered`.
- `complaint_rate = complaints / delivered`.
- `sessions_per_clicker = sessions / unique_clickers`.
- `engaged_rate = engaged_sessions / sessions`.
- `lead_cr = leads / sessions`.
- `leads_per_1000_delivered = leads / delivered × 1000`.

Показывать знаменатель рядом с коэффициентом. Для baseline использовать weighted rate по суммарным числителям и знаменателям плюс медиану campaign-level rate.

## 6. Карта ссылок и post-click

Карта UniSender показывает распределение кликов внутри письма, но all clicks не равны уникальным людям. Для каждой позиции разделять:

1. клики в письме;
2. визиты с `utm_content`;
3. качественные визиты;
4. цели и заявки;
5. продажи.

Без уникального `utm_content` одинаковые URL из разных мест нельзя надёжно сравнить. Без click ID анализ остаётся агрегированным.

## 7. Расхождения источников

Ожидать, что кликов UniSender больше или меньше визитов аналитики из-за повторных кликов, ботов, блокировщиков, согласия на аналитику, редиректов и разных правил идентификации. Не складывать Метрику и Matomo. Объяснять расхождение и контролировать его динамику.

## 8. Сила выводов

- Один эпизод: наблюдение или гипотеза.
- Повторение в 3+ сопоставимых кампаниях: вероятный паттерн.
- Стабильность на 25–30 кампаниях или в корректном эксперименте: рабочее правило.
- Причинный вывод: только при контролируемом тесте или достаточно сильном квазиэксперименте.

При небольшой базе подписчиков тестировать одну крупную гипотезу за кампанию и накапливать evidence между письмами.
