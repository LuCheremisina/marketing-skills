# Редакционный конвейер новости

Готовить управленческий разбор: событие → подтверждённые изменения → последствия для аудитории → действие, которое можно проверить.

## Режим

- `draft`: материал и metadata без изменений публичных страниц.
- `integrate`: по поручению внести материал в текущую архитектуру проекта.
- `publish`: подготовить интеграцию; commit, push и deploy выполнять только в явно разрешённом объёме. Проверить опубликованный URL после внешнего действия.

## Работа

1. Прочитать [редакционную политику](references/editorial-policy.md) и [формат](references/news-format.md). Получить бренд-профиль текущего проекта и цель материала.
2. Проверить первоисточник, дату события, дату публикации, доступность и статус функции. Для спорного существенного тезиса искать независимое подтверждение. Недостаток данных обозначить.
3. Написать одну центральную мысль; разделить факт, вывод автора, гипотезу и рекомендацию. Не выдавать анонс за массовый запуск и результат компании за собственный кейс.
4. Построить F0–F5; провести редактуру понятным языком. Сохранять оговорки, ссылки и единицы сравнения. Не добавлять частотность Wordstat ради новости.
5. Если используется глоссарий проекта, проверить терминологию по [правилам](references/glossary-sync.md). Не создавать ссылки на отсутствующие страницы.
6. Подготовить обложку через доступную разрешённую возможность: [cover-pipeline.md](references/cover-pipeline.md). Наличие промпта не считать готовым изображением.
7. Для интеграции осмотреть существующие collections, routes, components, build scripts, feed и sitemap. Прочитать [integration.md](references/integration.md). Не предполагать конкретный framework, папку или private script.
8. Провести [QA](references/qa-checklist.md), показать артефакты и не проверенное. При публикации отдельно подтвердить внешний результат.

## Ограничения

Не выдумывать цитаты, цены, результаты и доступность. Не менять дизайн проекта или пользовательские правки. CTA выводится из задачи читателя и утверждённого предложения; рекламная вставка и ссылка на методолога не обязательны. Автоматические сборочные статусы не выдавать за публикацию или индексирование.

## Входы и среда

Получить цель, аудиторию, исходный материал и предоставленный пользователем бренд-/авторский профиль. Профили и результаты хранить в каталоге задачи вне установленного навыка. Не использовать методолога навыка как автора материала по умолчанию.

Определить доступные инструменты чтения, поиска, работы с файлами и генерации медиа. Название инструмента зависит от платформы: использовать реально объявленную возможность. Нет подключения — принять разрешённую выгрузку, назвать ограничение или остановить зависимый этап; не выдумывать данные и не обходить авторизацию.

Для скрипта сначала определить абсолютный путь к установленной папке навыка; передавать полный путь к скрипту и входам. Команды в этом документе иллюстрируют аргументы. Не предполагать текущую рабочую папку. В Claude Code разрешён путь через `${CLAUDE_SKILL_DIR}`; в остальных средах использовать путь, сообщённый загрузчиком. Без исполнения скриптов указать ручную проверку и её пределы.
